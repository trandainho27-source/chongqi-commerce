# 嘀嘀批发货源对接

## 当前范围与验收状态

本次提供公开商品目录、平台图标、地区图标以及「货源对接」店主后台。采购模式为 **店主逐笔确认 → 使用供应商余额采购 → 卡密加密入库 → 现有商城销售和发货**。顾客下单不会触发供应商扣款。USDT 实付验收独立进行。

2026-10-13 公开页面整理出 114 个商品、9 个分类。113 项可确定供应商编号，1 项缺货商品未暴露编号。保留商品名称中的地区、账号年龄、协议登录等限制；没有照搬供应商长篇商品描述或售后承诺。导入的售价为当时公开零售价，**未自动加价**。店主需在商品管理中复核说明和售价后备货销售。网站库存只统计本店实际入库卡密，不使用上游库存冒充本店库存。

当前只有用户提供的请求接口文档，尚无供应商 API Token 和成功响应示例。适配器已按以下明确结构实现并通过模拟测试，**不代表与真实供应商完成联调**。未知响应会停止入库并保留采购记录。首次真实采购前应提供账户、商品、订单成功响应的脱敏示例以核对字段；切勿把尚未核对的适配器直接当作已验证生产接口。

## Cloudflare 配置

在 Worker 的「设置 → 变量和机密」中配置并部署，机密不要写入 GitHub：

| 名称 | 类型 | 用途 |
| --- | --- | --- |
| `DIDIPIFA_API_TOKEN` | Secret | 嘀嘀批发 API Token，与 TronGrid 密钥无关 |
| `DIDIPIFA_PURCHASE_ENABLED` | Text | 缺省关闭；响应核对完成后设 `true` 才允许真实采购 |

沿用原 `INVENTORY_KEY` 加密入库，不要更换已有库存的密钥。演示环境禁止实际采购。账户 API 权限、余额及供货资格由供应商确认。

进入 `/admin` →「货源对接」，先查询余额、同步商品，再获取报价。查询、同步和报价都不购买商品。报价五分钟有效；采购确认会再次检查库存与价格。仅店主可访问该功能，写操作检查 Origin 和 CSRF。无需把 Token 粘贴到前端页面。

## 接口与响应约定

固定 HTTPS 基础地址 `https://didipifa.net/api/v1`，使用 `Authorization: Bearer ...` 和 `Accept: application/json`；禁止重定向，15 秒超时。以下 JSON **为本项目适配器约定的测试示例，并非已读取的供应商真实响应**：

```json
{"data":{"balance":"100.00","currency":"CNY"}}
```

```json
{"data":[{"id":541,"name":"商品名称","price":"3.60","stock":50,"delivery_type":"automatic"}]}
```

`GET /goods/{id}` 的 `data` 为单个上述商品对象。列表亦支持 `data.goods`、`data.items` 或 `data.data`；分页需提供 `last_page` 或 `meta.last_page`，最多 20 页、1000 项。商品别名支持 `goods_id`、`goods_name`、`actual_price`、`in_stock`。发货类型仅识别 `automatic/auto`、`manual/service` 或明确布尔值 `automatic/is_auto`，不猜测数字类型码；公开详情明确证明自动发货的已有映射可作为类型补充。

```json
{"data":{"order_sn":"DIDI-001","goods_id":541,"quantity":1,"request_id":"CQ-SUP-...","status":"fulfilled","total_price":"3.60","currency":"CNY","cards":["一条完整交付卡密"]}}
```

订单必须核对商品编号、数量、已完成状态、总金额与卡密条数。支持完成状态 `fulfilled/completed/delivered/success`，金额支持 `total_price/total`，`cards` 须为字符串数组。`request_id` 如返回必须匹配。未识别的数字状态码、卡密对象、附件或下载链接不会被自动当作卡密入库，需要根据真实文档适配。

## 扣款恢复与边界

- 报价时由本系统生成唯一 `CQ-SUP-...` 并持久保存；采购参数从数据库取值，浏览器不能修改商品和数量。
- 未知结果重试沿用相同 `request_id`；获得供应商 `order_sn` 后优先 `GET /orders/{order_sn}`。不自动新建采购补偿失败，也不自动批量重试。
- 上游接口没有最高成交价或原子锁价参数。确认前的复查无法完全消除复查与采购之间价格变化的窗口；采购实际金额超过报价时留在待核查状态。不要把确认报价视为供应商承诺的扣款上限。
- 接收结果先加密保存，再校验并事务入库；重复卡密、条数不符、错商品或字段异常均不入库。采购与卡密唯一约束防止二次入库；重试不会用新采购编号重新购买。
- 卡密不回显在采购列表，日志不记录 Token、完整响应或卡密。`Request-Id` 单独保存，便于联系客服定位。
- 本站把所有供应商调用合计限制为每分钟 45 次，预留余量。Token 被其他站点共用时，仍可能收到供应商 429，按原记录稍后重试。
- 暂不传 `notify_email`，不把顾客邮箱送到供应商；供应商是否给账户邮箱发送默认发货邮件由其 API 行为决定。
- 手工服务、业务链接、需要额外参数的商品及无商品编号条目只作目录展示，不允许通过该采购流程购买。

## 图标与数据维护

平台标识由站内组件绘制，国旗/地区旗使用 `lipis/flag-icons` v7.3.2 的本地 SVG，MIT 许可保存在 `public/flags/LICENSE.txt`。无外链图片依赖。

`data/didipifa-catalog.json` 保存事实快照。`scripts/generate-supplier-catalog.mjs` 可复现 `0006_didipifa_catalog.sql`，不访问网络或数据库。迁移使用 `INSERT OR IGNORE`，不覆盖现有编辑、不添加卡密、不扣款。API 同步只更新货源参考价、库存与同步时间；已有商品的本店售价、描述、上下架状态不变。新增 API 商品放入「其他货源商品」。
