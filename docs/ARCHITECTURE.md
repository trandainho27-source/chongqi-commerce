# 架构与验证范围

前端 React → Vinext 路由 → commerce API → D1。所有关键业务状态持久化；localStorage 仅用于本机购物车与本机订单凭证。

## 数据一致性

- 下单读服务端商品价，随后在一个 batch 内创建订单、创建明细、分配库存、检查全量预留。
- CHECK 事务守卫检查商品仍在售、报价一致、数量限制、订单金额一致以及每个明细预留数量。
- 即使两个请求都先读到同一库存，第二个事务无法凑齐预留数量，整体回滚。
- 交付事务检查订单未过期，唯一支付流水通过数据库索引约束，事务守卫要求每个商品全部交付才能成为 fulfilled。
- 原始卡密 AES-256-GCM 加密；商品 ID 作为附加认证数据，SHA-256 指纹用于去重。

## 身份与访问

PBKDF2-SHA256（100,000 次，随机盐）保存密码；256 位随机会话令牌仅存哈希，Cookie 为 HttpOnly / Secure / SameSite=Strict；写操作需要 Origin 与会话 CSRF 校验；后端执行角色授权。订单密钥同样只存 SHA-256 哈希，不使用连续订单号作为访问凭据。公开入口有按 IP 与分钟限速。

后台会话及订单响应 `Cache-Control: no-store`。请求输入只作为参数化 SQL 或 React 文本显示。CSV 导出转义公式前缀。

## 已验证

自动集成测试使用 Node 内置 SQLite 模拟 D1 prepare / batch，并执行真实迁移与业务 API，覆盖管理员初始化、订单金额、查询凭证、库存竞争回滚、卡密去重与加密、确认收款、幂等、取消、过期、角色权限、CSRF、Origin、退款记账、工单、HMAC 回调及 AES 上下文认证。

编译检查与部署构建也必须通过；`npm run verify:worker` 在 Cloudflare workerd 中验证 4 个服务端页面、真实 D1 迁移、登录会话、下单和加密发货。浏览器视觉与交互 QA 尚未运行。SQLite 集成测试验证 SQL 事务和约束；不能替代 Cloudflare 生产环境的负载、网络、支付平台实单和外部安全验证。正式环境不预置管理员密码、不自动创建真实商品、不启用演示登录。

## 当前边界

单商户、CNY 标价与 TRC20 USDT 收款、每个商品一个 SKU、卡密式交付、访客订单。未实现会员账户、余额、分销、多供应商、多商户、其他支付币种、文件交付或自动邮件。Vinext 依赖版本为 beta，升级前应运行完整检查；稳定性判断应基于实际环境测试。

## TRC20 支付

`tron.ts` 负责固定主网 RPC、地址校验、整数换算与官方合约日志解析；`payments.ts` 管理唯一支付单、分页游标、扫描租约、到账记录和异常。Worker 的 `scheduled` 调用对账服务，付款页和店主可以触发同一核验服务。查询配置只含公开地址和读取 API Key，系统没有钱包签名或转出资金能力。

数据库永久约束 `(address,amount_units)`，到账按 `txID:logIndex` 唯一。支付单固定报价、收款地址与有效期，后续环境配置变更不改旧订单。完整到账回执与交付共用订单的事务守卫。监控和补查均按实际金额定位订单，不采用客户自报的付款金额。

新增测试覆盖 Base58Check、整数报价、未配置与演示关闭、支付幂等、金额不复用、取消竞争、固化交易与假币校验、跨订单冒领、少付多付、重复到账、过期到账、交付失败回滚、节点故障、分页与后台巡检、店主权限。集成测试的链上响应是受控模拟，不代表已经做过主网实际收款。
